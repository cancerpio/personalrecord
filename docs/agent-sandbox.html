Agent 沙箱操作手冊

讓 Claude Code 和 Codex 在隔離容器裡全權限執行、不問授權，並可用 git worktree 平行開多個。 容器就是邊界，所以兩個 agent 都以 bypass 模式跑。

只用於你自己信任的 repo

bypass 模式下，惡意專案可以讀走容器內 ~/.claude、~/.codex 的登入憑證。 這是 Anthropic 官方明列的限制。不可信的第三方程式碼請用 VM 或 cloud session。

前置作業（每台機器一次）

  1. 確認 git 版本 ≥ 2.48

    worktree 的相對路徑需要這個版本，否則主機端無法操作容器建出來的 worktree。

    主機 · zsh
    brew install git && git --version
git version 2.50.1 (Apple Git-155)

  2. 把 superpowers skills 接到容器讀得到的位置

    容器內以唯讀掛載這個路徑。superpowers 升版後版本號目錄會換，重跑一次 ln -sfn 指到新版即可。

    主機 · zsh
    mkdir -p ~/.agent-skills
ln -sfn ~/.claude/plugins/cache/claude-plugins-official/superpowers/6.3.0 \
        ~/.agent-skills/superpowers
ls -l ~/.agent-skills/
superpowers -> /Users/…/superpowers/6.3.0

不需要 bootstrap。 早期版本要求先在主機建一個拋棄式 worktree 來升級 .git/config，那是因為當時把 .git/config 掛成唯讀。現在已改用 core.hooksPath 檢查取代，這個步驟整個取消了。

    主機 · 專案根目錄
    npx @devcontainers/cli up --workspace-folder .

  2. 進容器

    主機 · 專案根目錄
    npx @devcontainers/cli exec --workspace-folder . bash

    登入狀態存在 named volume，只有 rebuild 才需要重登。瀏覽器回調失敗時，把畫面上的代碼貼回終端機。

    claude       # 依提示登入後離開

    cc 與 cx 是 image 內的執行檔，會在防火牆未就緒時拒絕啟動。

平行開多個 agent

沒有 worktree 的話，agent 和你共用同一個 checkout——它一切分支，你編輯器裡的檔案就整批被換掉。 agent-wt new 一次處理四件事：建 worktree 與分支、裝依賴、配一個不重複的 PORT、在 tmux 開視窗。

容器 · agent-wt
agent-wt new feat-a claude "把動作總覽的欄位改成三欄"
added 162 packages in 3s
agent-wt: worktree=/workspaces/personalrecord/.worktrees/feat-a 分支=agent/feat-a PORT=3120
agent-wt: [claude] 已在 tmux agents:feat-a 啟動 → tmux attach -t agents

cat .worktrees/feat-a/.git
gitdir: ../../.git/worktrees/feat-a   # 相對路徑，主機端才操作得到

agent-wt new feat-b codex @docs/some-prompt.md
tmux attach -t agents   # 切視窗：Ctrl-b n / Ctrl-b w

dev server 要用 .agent.env 裡的 $PORT： npm run dev -- --host 0.0.0.0 --port $PORT

收成（主機或容器都可以）

沒有 agent-wt diff 或 agent-wt rm——那些本來就各是一行原生 git，包起來不會更短。

主機 · 路徑前綴和容器不同，但相對連結兩邊都通
git worktree list
/Users/cancerpio/Project/personalrecord                  a908449 [main]
/Users/cancerpio/Project/personalrecord/.worktrees/feat-a a908449 [agent/feat-a]

git diff main...agent/feat-a
git merge agent/feat-a
git worktree remove .worktrees/feat-a && git branch -d agent/feat-a
git push

放 agent 進去之前先 push

專案目錄在容器內可寫（agent 要能改程式碼），.git 也在裡面。 AGENTS.md 禁止它砍歷史，但那是文字約束不是機制。 沒 push 的 commit 被砍掉就是沒了；先 push，最壞情況只是重新 clone。

擋得住什麼

威脅狀態靠什麼擋
誤碰專案外的檔案（~/.ssh、其他 repo）擋住容器邊界
弄壞開發環境（nvm、全域 CLI）擋住容器邊界
一直要按授權解決兩個 agent 都 bypass
改到會在主機執行的檔案擋住.devcontainer/、.git/hooks/、.claude/、AGENTS.md、.mcp.json 唯讀
git push擋住容器內沒有憑證（未掛 ~/.ssh、無 credential helper）
agent 自己關掉防火牆擋住sudo 收斂成只能跑防火牆腳本且不能帶參數
VS Code IPC 逃逸（容器內在主機執行指令）不存在走 CLI，容器內沒有編輯器 process
把東西往外送部分出站白名單，但 IP 粒度且無紀錄
砍掉 .git 歷史擋不住設計如此，靠「先 push」

已知的洞：單檔唯讀 mount 會靜默脫鉤

AGENTS.md 與 .mcp.json 是單一檔案的 bind mount。工具改檔案常用 「寫 .lock 再 rename」，換的是 inode；主機那側一旦換掉檔案， 容器裡的 mount 就脫鉤、檔案變回可寫，沒有任何錯誤訊息。目錄的 mount 沒這問題。

最常觸發的情境很日常：你在主機上編輯 AGENTS.md，它自己的保護就掉了。 開發這份設定時實測到，一次就中：

容器 · 主機剛編輯過 AGENTS.md 之後
verify-sandbox
  FAIL  AGENTS.md 不可寫  → <rc=0>
PASS=20 FAIL=1
有項目未通過，請先修好再放 agent 進來。

修法是重建容器：

主機
docker rm -f $(docker ps -aq --filter label=devcontainer.local_folder=$PWD)
npx @devcontainers/cli up --workspace-folder .
PASS=21 FAIL=0

緊急關閉防火牆：sudo 已收斂，容器內辦不到。從主機下 docker exec -it -u root <容器> bash。

本專案多出來的

功能官方本專案為什麼
Codex 支援無有 Codex CLI 的網路只有開關、沒有網域白名單（managed allowlist 是 ChatGPT Work 的功能），所以容器是唯一 vendor-neutral 的邊界
防火牆 fail-closed無有 trap lockdown ERR：DNS 不通、GitHub meta 抓不到等任一步失敗，就把政策設成 DROP 再退出，而不是留下一個沒防火牆的容器
防火牆就緒旗標無/run/firewall-ok cc / cx 在旗標不存在時拒絕啟動
白名單獨立成檔寫死在腳本allowed-domains.txt 放在 image 內，agent 改不到；要加網域不必動腳本
sudo 收斂保留完整 sudo只能跑防火牆腳本且不能帶參數 否則 agent 可以 iptables -F，或指向自己寫的全放行清單重建防火牆
控制面唯讀無5 個路徑 .git/hooks、.mcp.json 這類檔案是由主機端工具執行的，寫進去等於在等你觸發
IPC 環境變數清空無remoteEnv 清 5 個 走 CLI 本來就沒有這條路，這是「萬一改用擴充套件開」的保險
邊界自我驗證無verify-sandbox（21 項） 單檔 mount 脫鉤是無聲的，沒有它會以為防護還在
平行 agent無agent-wt new worktree + 依賴 + 不重複的 PORT + tmux 視窗
行為規則無AGENTS.md Codex 原生讀這個檔名；Claude 由 cc 以 --append-system-prompt 注入
node_modules不處理named volume 主機是 macOS，原生 binary 是 darwin-arm64，掛進 Linux 容器會找不到 binding

官方有而本專案刻意不要的

官方的做法本專案理由
Reopen in Container 為主要用法只用 CLI 擴充套件會注入 IPC socket、轉發 SSH agent 與 GPG，容器內可反向在主機執行指令。Trail of Bits 的結論是不建議用於不可信程式碼
zsh + powerlevel10k + git-delta不裝 agent 不需要好看的 shell，image 可以小一點
CLAUDE_CODE_VERSION=latest ＋ 自動更新釘死版本 Anthropic 自己也建議：要可重現的 build 就用 npm i -g …@X.Y.Z 而非 feature
eslint / prettier / gitlens 擴充只留兩個 agent 的擴充 編輯器在主機，容器內的擴充用不到

三個容易誤解的設計

看起來奇怪的地方原因
沒有 CLAUDE.md 建了的話主機上的 Claude session 也會載入 AGENTS.md，而那份講的是「你在容器內、權限全開」——在主機上是錯的。容器內改由 cc 以 --append-system-prompt 注入，來源固定是唯讀的根目錄副本，不是 worktree 裡那份可寫的 checkout
cc／cx 是執行檔不是 alias agent-wt 產生的 runner 是非互動 bash，不會 source /etc/bash.bashrc，函式放那裡用不到；而且烤進 image 後 agent 改不掉
sudo 收斂在 post-create.sh 而非 Dockerfile devcontainer features 疊在 image 之上、以 root 執行，會把 NOPASSWD:ALL 寫回來，抵銷 Dockerfile 裡做的任何收斂。所以收斂必須是最後一步
