# 設計：動作總覽改為可點擊鑽取，移除 Sparkline 區塊

日期：2026-08-30

## 目標

點「最近動作總覽」的任一列，底下的 Performance Overview 圖表就切換到該動作。
同時移除 Sparkline 區塊。

## 受眾檢查

- **來源**：起因是使用者實際使用時發現「幾乎不看 1RM/3RM/5RM 那幾個區塊」。
  但**本次採用的解法（點列鑽取）是使用者自己的推測**，非從摩擦直接得出——
  原話：「這個是我自己猜測的改善項目，得實驗才知道」。
- **只解決我個人的問題／進階訓練者／一般使用者**：三題皆為**待驗證**，不是「不知道」——
  使用者明確表示要做出來看。
- **對我變差**：同樣待驗證。使用者要求把移除前的樣貌記錄下來以便判斷與回退，
  故本文設有〈移除前的樣貌〉一節。

## 起因與探索過程

使用者最初的訴求是兩件事：想要能自由開關 Dashboard 各區塊，以及 PR 相關區塊
「UI 不如新增的那些、三個趨勢太佔空間」。並指出兩個原因：目前處於增肌減脂＋
控制大重量的週期，不關注最大重量；以及顯示本身有問題。

探索後發現訴求裡混了兩個不同的問題：

- **問題 A（現在就壞）**：Sparkline 區塊挑選任意、佔空間、風格過時。
- **問題 B（結構性）**：Dashboard 固定，但訓練週期會變（增肌／力量／舉重為主軸），
  該看什麼隨之改變。

使用者選擇**先修 A，修好再判斷還需不需要 B 的開關機制**——「不知道，可能要等修好以後才會知道」。
因此本次不處理區塊開關。

## 移除前的樣貌（rollback 依據）

> 這一節是使用者明確要求保留的。程式碼本身在 git 歷史裡，但**為什麼移除、
> 移除的是什麼東西**必須寫下來，否則日後只看到一個空缺。

### 檔案

`src/components/SparklineRow.vue`（本次刪除），
以及 `src/views/DashboardView.vue` 中的 `sparklines` computed 與 `.sparklines-container` 區塊。

### 它實際顯示什麼

每列一個 `.status-pill`，左側 48×48 的彩色圓角 icon 容器（上升／下降／持平／無資料
四種箭頭 SVG），中間動作名稱，右側趨勢文字如 `→ 連續 3 次上升`。
顏色：上升綠 `#10b981`、下降紅 `#ef4444`、持平橘 `#fb923c`、無資料灰 `#a1a1aa`。

### 三個具體問題

**1. 顯示哪三個動作是任意的。** `uniqueExercises.value.slice(0, 3)`——陣列的前三個，
沒有任何依據。原註解寫「to keep it clean (MVP Apple HIG)」。
使用者感覺「不如新增的區塊」，成因有一部分是它挑的內容本來就沒有根據。

**2. 空間效率極差。** 每個 pill 高 72px（`padding 12px×2 + icon 48px`），
三個加間距約 **240px**，顯示 6 個資訊點（3 動作名 + 3 趨勢標籤），
約 **40px 換一個資訊點**。對照「最近動作總覽」每列 30px、4 欄，約 **7.5px 換一個資訊點**。
密度差五倍以上。

**3. 它叫 Sparkline，但沒有畫任何 sparkline。** `getChartSeriesForExercise` 算出的整條序列，
在元件中只被用於 `data.data.length >= 2` 這個判斷（決定是否套一個 CSS class）。
所有 SVG 皆為固定座標的箭頭圖示，沒有一條線來自資料。
也就是說它付出了圖表元件的垂直空間與計算成本，最後顯示一個箭頭和一個詞。

**4. 視覺語彙與專案既有原則衝突。** class 名為 `.status-pill`，具備 `border-radius`、
`border`、`inset box-shadow`，內含自帶陰影的 48px 圓角彩色 icon——是 app icon 加卡片的語彙，
但**不可點擊**，屬假的可操作暗示。
而 `openspec/specs/exercise-streak-overview/spec.md` 明訂：
「SHALL NOT 使用 pill、emoji、警示 icon 等警報語彙——本能力不通知，使用警報符號卻無後續行動
在語意上自相矛盾。」新元件依此原則設計，舊元件正是該原則要防的東西。

### 如何回退

`git revert` 本次 commit 即可還原檔案與掛載點。若只想恢復顯示而不恢復實作，
請注意上述問題 1 與 3 尚未解決——直接還原等於把同樣的缺陷放回去。

## 關鍵發現：動作詳細圖已經存在

一度考慮新增「動作詳細頁」路由。查證後發現**不需要**：

`DashboardView.vue` 的 `chartSeries` 已經是「單一動作的詳細趨勢圖」——
`filters.exercise` 選一個動作、`filters.rmType` 選 PR/3RM/5RM、加上年月篩選，
畫出該動作重量趨勢 + 體重 + 體脂的雙軸圖。

差別只在**入口**是頁面最底部的下拉選單，而不是點使用者正在看的那一列。

因此本次不新增路由、不新增頁面、不新增資料邏輯，只把總覽表接到既有圖表。

### 業界佐證

查 Hevy 的產品說明，未見「把動作釘選到儀表板」的功能。其分工是儀表板放彙總指標
（訓練時間、總容積、總次數），個別動作的趨勢**從動作點進去看**。
自訂集中在課表層級而非儀表板層級。
（信心程度：來自產品說明頁，非實際操作，可能有遺漏。）

這支持「移除固定三格、改為鑽取」的方向。

## 決策

1. **移除 Sparkline 區塊**，刪除 `SparklineRow.vue`。省下約 240px。
2. **`ExerciseOverview` 的資料列可點擊**，`emit('select', exercise)`。
   僅加游標與按下態，**不加箭頭或 icon**——沿用上述「不用警報語彙」原則。
   表頭列不可點。
3. **`DashboardView` 接收事件**：設定 `filters.exercise`，`nextTick` 後捲動至圖表區塊。
4. **`FilterControls` 不動**，下拉選單保留為備援入口。

### 點列只改 exercise，不動年月

主圖同時吃 `year` / `month` 篩選（`year` 預設為當年）。若使用者已篩在某年某月，
而所點動作在該範圍無資料，圖表會顯示既有的空狀態。

**仍選擇只改 `exercise`。** 替使用者清掉他自己設定的篩選，屬於「系統替使用者做了
他沒要求的決定」——與 #19 討論中否決 B 案的理由同一類。
而本方案的失敗是**可見的**（空圖加說明文字），不是靜默的。

## 明確不做

- **區塊開關／版面偏好**：使用者要求先修好再判斷是否需要。
- **把趨勢線畫在儀表板上**：一度選定此方向，後因發現詳細圖已存在而改為鑽取。
- **鍵盤操作**：可點擊的列為 `div` + `@click`，與專案既有做法一致
  （`RecordView` 的 session-card 同樣如此）。無鍵盤導覽支援。

## 測試

**本次完全沒有自動化測試。** 沒有 store 邏輯變更，而元件互動無法測試——
前端元件測試基礎設施尚未建立（todo #10）。以人工驗證：點列後圖表切換至該動作並捲動到位。

這是本次改動最大的弱點，如實記錄。
