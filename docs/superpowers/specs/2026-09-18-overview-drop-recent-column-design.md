# 設計：動作總覽砍掉「近2週」欄

日期：2026-09-18

TODO #27。手機上動作名稱被截斷到分不出是哪個動作。本次不改資料模型、不新增寫入路徑，
只調整一張表的欄位預算，並把一個聚合值換一個地方承載。

## 需求

使用者原話：「現在手機的最近12週動作總覽 的動作實在是縮得太超過了，
我根本看不到那動作是啥，我現在覺得應該要偵測裝置為手機時，這邊的排版要調整一下」。

**受眾**：用出來的｜僅我：否，任何人在手機上都會碰到｜對我變差：現在就是變差的狀態。

## 問題查證

`.streak-row` 目前是 `grid-template-columns: 14px minmax(0, 1fr) auto 44px 48px`，`gap: 10px`。

iPhone 375pt 的可用寬度：

| 項目 | 寬度 |
|---|---|
| 視窗 | 375 |
| `#app` padding（20 × 2） | −40 |
| `.streak-panel` padding（16 × 2） | −32 |
| **表格可用寬度** | **303** |

303px 怎麼分：

| 欄 | 寬度 |
|---|---|
| caret | 14 |
| 動作（`1fr`，吃剩下的） | **101** |
| 近2週（`auto`，`12組·96次`） | 約 56 |
| 最重 | 44 |
| 持續週數 | 48 |
| 四個 gap | 40 |

而 Firestore 實際資料（2026-09-18 查詢 `training_sessions`）的動作名是英文全稱：

| 動作名 | 14px 下約需 | 101px 內顯示為 |
|---|---|---|
| `Barbell Overhead Press` | 150px | `Barbell Overh…` |
| `Dumbbell Bench Press` | 137px | `Dumbbell Ben…` |
| `High Bar Squat` | 96px | 剛好完整 |

兩個 press 動作截斷後的前綴幾乎一樣。320pt 的機器上動作名只剩約 46px。

## 否決的方向：加寬度斷點

使用者的原始構想是「偵測裝置為手機」。不採用，理由有二。

**一、方向相反。** 整個 `src/` 只有一個 `@media`，而且是 `prefers-color-scheme`
（`src/assets/main.css:19`）——**零個寬度斷點**。這是 LIFF app，手機是主要形態，
桌機才是邊緣情況。加 `max-width` 斷點等於宣告「現在這版是桌機版、手機是特例」，
與實際使用剛好相反。

**二、問題不在斷點。** 五欄擠在 303px，而動作名是唯一吃 `1fr` 的一欄——
其他四欄全是固定或 `auto`，先拿走自己要的，剩下才給動作名。
加斷點只是在另一個寬度下重寫同一份欄位分配，需要維護兩套定義，
而三欄在 303px 下本來就夠用。該修的是欄位預算。

## 決策

### 砍掉「近2週」欄

該欄正好是吃掉 56px 的那一欄，而且它在展開後重複——#26 的詳細面板已有
「近 14 天」逐日明細（每日組數、容積、重量×次數）。

砍掉後少一欄也少一個 gap：

| | 砍之前 | 砍之後 |
|---|---|---|
| `grid-template-columns` | `14px 1fr auto 44px 48px` | `14px 1fr 44px 56px` |
| gap 總計 | 40 | 30 |
| **動作名可用寬度** | **101** | **159** |

`Barbell Overhead Press`（約 150px）放得下。

### 順帶把持續週數欄 48px → 56px

「持續週數」五個字在 11px 加 `letter-spacing: 0.04em` 下約 57px，現在就已經溢出 48px 的欄寬。
少掉的那個 gap 剛好補上，動作名仍有 159px（只比不調整的 167px 少 8px，
而 159px 已足夠容納目前最長的動作名）。

### 14 天總計搬進詳細面板

砍掉欄位會讓「近 14 天總共 X 組 Y 次」這個聚合值消失。面板有逐日明細但沒有總數，
要自己把每天的組數加起來。因此把總計放進面板「近 14 天」那一行的標題：

```
近 14 天 · 5組·27次
```

而不是新增一個區塊——它是那一段的標頭資訊，不是另一段內容。

`recentSets` / `recentReps` 隨之從 `exerciseOverview` 的列移除。查證過全專案，
移除後唯一的消費者 `ExerciseOverview.vue` 也不再需要它們，留著就是死欄位。
改由 `getExerciseRecentDetail` 回傳 `totalSets` / `totalReps`——同一個 14 天視窗、
同一份來源資料，由已經在算逐日明細的那個 getter 一併算出。

### 空視窗的顯示：面板已有處理，不需要破折號

總覽那一欄原本在視窗內無紀錄時顯示破折號，用來與「0組·0次」區隔。
搬進面板後不需要這個區隔——面板在 `days` 為空時走的是另一條分支，
顯示「近 14 天未練 · 上次 MM-DD」，比破折號講得更清楚。
因此總計只在 `days` 非空時顯示。

## 取捨與影響

**總覽不再回答「最近做了多少」。** 這是刻意的。砍掉後總覽回答兩個問題：
「這個動作我目前持續幾週沒換」和「歷來最重多少」；「最近做了多少」要點開才看得到。
代價是多一次點擊，換來的是不點開就看得出那一列是哪個動作——
而看不懂動作名的時候，後面三欄數字都是無主的。

**spec 的 `Recent Training Volume` 需求換能力承載。** 從
`openspec/specs/exercise-streak-overview/spec.md` 搬到
`openspec/specs/exercise-detail-panel/spec.md`。需求沒有消失，
14 天滾動視窗、一筆算一組、`reps` 缺失以 0 計、視窗內無紀錄的行為全數保留，
只是宣告在詳細面板這個能力底下。

**如果砍完還是嫌窄**，下一個要試的是兩行列（動作名獨占第一行、數字右對齊第二行）：
資訊全保留，代價是列高 30px → 約 44px，12 個動作多佔約 170px 版面。
本次不做，因為砍欄位的 159px 已經夠用，而兩行列會改變整張表的掃描節奏。

## 明確不做

- **不縮寫動作名**（`Barbell Overhead Press` → `OHP`）。動作名是自由文字，
  #12 動作身分一致性尚未完成，無法可靠對應縮寫；硬做會在名稱分岔時對應錯。
- **不改動作名的字級**。把 14px 縮到 12px 能多塞兩三個字元，但那是把
  「看不完」換成「看得完但看不清」，在健身房裡更糟。
- **不縮減任何欄位的計算範圍**。最重欄維持掃描全部歷史。
